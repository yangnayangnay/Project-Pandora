================================================================================
  Project Pandora - 客户端与服务端消息传递说明
  生成日期: 2026-10-09
  架构: Android客户端 ←→ Spring Boot后端 ←→ H2数据库
  通信协议: HTTP/REST + JSON
  认证方式: JWT Bearer Token
================================================================================

【一、通信基础信息】
--------------------------------------------------------------------------------
  基础URL:     http://10.0.2.2:8080/api/  (模拟器访问宿主机)
  请求格式:    Content-Type: application/json
  认证头:      Authorization: Bearer <JWT Token>
  响应格式:    { "code": 200, "message": "success", "data": {...}, "traceId": null }
  错误格式:    { "code": <errorCode>, "message": "<errorMsg>", "data": null }
  
  客户端技术栈: Retrofit2 + OkHttp3 + RxJava3
  服务端技术栈: Spring Boot 3 + JdbcTemplate + JWT(HMAC-SHA384)
  
  5种角色: ADMIN(管理员) / FOUNDER(创始人) / DEPT_HEAD(部门主管) 
           / TEAM_LEADER(团队领导) / EMPLOYEE(普通员工)

【二、认证模块 (AuthApi ←→ AuthController)】
================================================================================

1. 用户登录
--------------------------------------------------------------------------------
  客户端 → 服务端:
    POST /api/auth/login
    Body: { "username": "yjl_founder", "password": "123465" }
    
  服务端 → 客户端:
    200 OK
    Body: {
      "code": 200,
      "data": {
        "user": { "id": 100, "username": "yjl_founder", "role": "FOUNDER",
                  "departmentId": 3, "teamId": 4 },
        "token": "eyJhbGciOiJIUzM4NCJ9...",
        "refreshToken": "eyJhbGciOiJIUzM4NCJ9..."
      }
    }
    
  说明: 登录成功后客户端保存token到TokenManager，后续请求自动添加Authorization头。

2. 用户注册
--------------------------------------------------------------------------------
  客户端 → 服务端:
    POST /api/auth/register
    Body: { "username": "...", "password": "...", "realName": "...",
            "idCard": "...", "email": "...", "phone": "..." }
    
  服务端 → 客户端:
    200 OK / 400 Bad Request(已存在) / 403(预登记未找到)
    
  说明: 注册时自动匹配employee_records表中的预登记信息。

3. 忘记密码
--------------------------------------------------------------------------------
  客户端 → 服务端:
    POST /api/auth/forgot-password
    Body: { "username": "...", "reason": "..." }
    
  服务端 → 客户端:
    200 OK (申请已提交，等待管理员审批)

4. 刷新Token
--------------------------------------------------------------------------------
  客户端 → 服务端:
    POST /api/auth/refresh
    Body: { "refreshToken": "..." }
    
  服务端 → 客户端:
    200 OK
    Body: { "data": { "token": "新token", "refreshToken": "新refreshToken" } }

5. 登出
--------------------------------------------------------------------------------
  客户端 → 服务端:
    POST /api/auth/logout
    Header: Authorization: Bearer <token>
    
  服务端 → 客户端:
    200 OK

【三、任务管理模块 (TaskApi ←→ TaskController)】
================================================================================

6. 创建任务
--------------------------------------------------------------------------------
  客户端 → 服务端:
    POST /api/task
    Header: Authorization: Bearer <token>
    Body: { "name": "任务名称", "isUrgent": true, "endTime": "2026-10-15",
            "assigneeId": 101, "isImportant": true }
    
  服务端处理:
    1. JWT验证 → 提取dispatcherId
    2. 校验assigneeId是否为当前用户或其下级
    3. INSERT INTO tasks (name, is_urgent, end_time, assignee_id, dispatcher_id, ...)
    4. NotificationService.detectNewTask(taskId, assigneeId)
    5. INSERT INTO notifications (target_user_id, type='NEW_TASK', content='...')
    
  服务端 → 客户端:
    200 OK
    Body: { "data": { "id": taskId, "name": "...", "status": "PENDING", ... } }

7. 查询任务列表
--------------------------------------------------------------------------------
  客户端 → 服务端:
    GET /api/task/list?status=PENDING&assigneeId=100&dispatcherId=null&showCompleted=false
    Header: Authorization: Bearer <token>
    
  服务端 → 客户端:
    200 OK
    Body: { "data": [ { "id": 1, "name": "...", "status": "PENDING",
                        "isUrgent": true, "endTime": "...", "assigneeId": 100, ... }, ... ] }

8. 更新任务状态
--------------------------------------------------------------------------------
  客户端 → 服务端:
    PATCH /api/task/{taskId}
    Body: { "status": "COMPLETED", "progressNote": "已完成开发" }
    
  服务端处理:
    1. 查询旧任务状态
    2. UPDATE tasks SET status='COMPLETED', progress_note='...'
    3. NotificationService.detectStatusChange(oldStatus, newStatus)
    4. 若状态变化则 INSERT INTO notifications
    
  服务端 → 客户端:
    200 OK / 404(任务不存在) / 403(无权限)

9. 获取四象限任务
--------------------------------------------------------------------------------
  客户端 → 服务端:
    GET /api/task/quadrant
    
  服务端 → 客户端:
    200 OK
    Body: { "data": { "importantUrgent": [...], "importantNotUrgent": [...],
                      "notImportantUrgent": [...], "notImportantNotUrgent": [...] } }

10. 获取下级用户列表
--------------------------------------------------------------------------------
  客户端 → 服务端:
    GET /api/task/subordinate/users
    
  服务端 → 客户端:
    200 OK
    Body: { "data": [ { "id": 101, "username": "...", "realName": "..." }, ... ] }

16. 月视图(含今日覆盖)
--------------------------------------------------------------------------------

  服务端 → 客户端:

    Body: { "data": { "2026-10-09": { "tasks": [...], "logs": [...] },

19. 导图四象限矩阵
--------------------------------------------------------------------------------
  客户端 → 服务端:
    GET /api/view/mindmap
    
  服务端处理:
    1. 查询 companyImportant:   assignee_id=用户 AND is_important=1 AND is_urgent=1
    2. 查询 companyDispatch:    dispatcher_id=用户 (公司任务派发)
    3. 查询 personalImportant:  assignee_id=用户 AND is_important=1 AND is_urgent=0
    4. 查询 personalLog:        work_logs WHERE user_id=用户
    
  服务端 → 客户端:
    200 OK
    Body: { "data": {
      "companyImportant": [ {任务对象}, ... ],
      "companyDispatch": [ {任务对象}, ... ],
      "personalImportant": [ {任务对象}, ... ],
      "personalLog": [ {日志对象}, ... ]
    } }
    
  客户端渲染:
    左上(红色#E74C3C):   重要且紧急 → companyImportant
    右上(棕色#D35400):   重要不紧急 → companyDispatch
    左下(绿色#27AE60):   紧急不重要 → personalImportant
    右下(蓝色#2980B9):   不重要不紧急 → personalLog

  服务端 → 客户端:
    200 OK (修改成功) / 400 (冷却期内，返回剩余天数)

--------------------------------------------------------------------------------
  客户端 → 服务端:
    GET /api/notification/poll?lastId=100

    SELECT * FROM notifications WHERE target_user_id=? AND id>? AND is_read=0
    
  服务端 → 客户端:
    200 OK / Body: { "data": [ {通知对象}, ... ] }
    
  客户端处理:
    遍历通知列表 → TaskNotificationService.showNotification()
    → 系统通知栏显示息屏通知
    
  说明: NotificationPollWorker继承Worker，通过WorkManager周期性执行(15分钟)。

32. 标记通知已读
--------------------------------------------------------------------------------
  客户端 → 服务端:
    PUT /api/notification/{id}/read
    
  服务端处理:
    UPDATE notifications SET is_read=1 WHERE id=?
    
  服务端 → 客户端:
    200 OK

【十、通知触发机制说明】
================================================================================

  通知触发时机:
    1. 创建任务时 → NotificationService.detectNewTask()
       → 写入 notifications 表 (type='NEW_TASK', target=assigneeId)
       
    2. 更新任务状态时 → NotificationService.detectStatusChange()
       → 状态从PENDING→COMPLETED时写入通知 (type='STATUS_CHANGE', target=dispatcherId)
  
  通知投递链路:
    后端写入notifications表
        ↓ (15分钟间隔)
    WorkManager触发NotificationPollWorker
        ↓
    GET /api/notification/poll
        ↓
    TaskNotificationService.showNotification()
        ↓
    Android系统通知栏(息屏通知)
  
  通知渠道:
    NotificationChannel ID: "task_notifications"
    重要性: IMPORTANCE_DEFAULT
    说明: 仅使用应用内消息+系统通知，不使用短信或邮件通知。

【十一、数据流总结】
================================================================================

  客户端到服务端的数据流:
    用户操作 → Activity/Fragment → ViewModel → Repository → Retrofit API
    → HTTP请求(带JWT) → Spring Boot Controller → Service → JdbcTemplate → H2数据库

  服务端到客户端的数据流:
    H2数据库 → JdbcTemplate查询结果 → Service业务处理 → Controller封装ApiResponse
    → HTTP响应(JSON) → Retrofit解析 → Repository → ViewModel(LiveData) → UI渲染

  本地缓存:
    Room数据库用于离线缓存部分数据
    TokenManager使用EncryptedSharedPreferences存储JWT Token
    
  关键设计:
    - 所有API请求自动附加Authorization头(OkHttp Interceptor)
    - Token过期时自动使用refreshToken刷新(OkHttp Authenticator)
    - 后端使用@Auditable注解自动记录审计日志
    - 角色权限通过JWT中的role字段在Controller层校验
