# 首页交互与每日事项弹窗调整

范围：本次用户要求的四项 Android 首页调整。由 Codex 直接完成，不再委派；禁止生成、复制、安装 APK，也不部署服务端。

## 行为与布局

1. 任务看板切换未完成/已完成时，仅重绘任务区域，保留事件纪原有 View、滚动位置及卡片高度。继续使用既有首页聚合接口，筛选响应中的事件数据不参与该次重绘；未新增接口或改变任务查询规则。
2. 两侧标题、说明和筛选融入紧凑标题区，移除事件纪说明的独立48dp占位。卡片间距8dp、阴影1dp；初始数据确定共同内容高度，最小160dp，上限为可用高度36%且最高280dp。内容超出时独立滚动，筛选过程中维持卡片边界。
3. 每日事项入口使用矢量加号，触控区域48dp，保留“新增事项”的无障碍描述；空列表提示指向加号。
4. 事项弹窗复用任务创建页的表单视觉语言：圆角描边内容卡片、带计数的多行输入、日期选择区、完整宽度保存按钮。仅保留事项已有字段，不增加任务派发或审核功能。

## 错误与生命周期

- 首次请求尚未完成时改变筛选，取消旧请求并确保事件纪仍能完成初始化。
- 事件纪已经载入后，任务筛选及失败重试不改变左侧；页面返回刷新时，事件内容相同则不重建。
- 页面销毁取消首页请求，避免旧响应触碰已经销毁的视图。
- 内容必填，最多500字。保存与删除期间防止重复提交；保存失败保留输入及所选日期。编辑事项保留二次确认删除。
- 弹窗提供滚动容器和键盘空间调整，使用现有浅色/深色资源，明确字段标签与图标按钮的无障碍说明。

## 验证边界

验证 Java/资源编译、JVM 单元测试及仪器测试源码编译。执行前检查 Gradle 任务图，仅允许不生成 APK 的任务；对比既有应用与仪器测试 APK 的路径、大小和修改时间。设备界面与手势验收不以源码编译替代。

实际结果：上述编译通过，136项JVM测试通过（含7项首页请求隔离回归），129个资源XML解析通过，APK变化数为0。未在设备或模拟器上进行界面与手势验收。验证记录为 `.build-temp/home-ui-android-plan.log`、`.build-temp/home-ui-android.log`、`.build-temp/home-ui-apk-before.json` 和 `.build-temp/home-ui-apk-after.json`。
