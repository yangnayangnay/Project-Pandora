# 工号登录与一次性创建完整人员资料

用户要求：管理员创建人员账号时以工号替代用户名，安卓使用工号登录；邮箱、手机号、身份证号、生日、部门、团队在创建时直接填写。用户进一步确认这六项资料全部必填，管理员登录保持不变。Codex 直接完成，不委派、不生成或安装 APK。

用户追加确认姓名也必填，沿用现有真实姓名字段。最终必填项为工号、密码、角色、真实姓名、邮箱、手机号、身份证号、生日、部门和团队。

- 工号使用现有账号唯一字段保存为字符串，保留前导零；新创建接口支持 employeeNo，兼容 username，二者同时出现必须一致。保留既有账号值，不执行数据批量改号。
- 创建表单包含工号、密码、角色、真实姓名及上述六项资料。部门加载失败可重试；先选部门再选该部门团队，切换部门清空团队。所有资料前后端均校验，组织必须有效且团队归属于部门。工号、邮箱、身份证号校验重复，生日有效且不晚于上海当日。
- 在一个事务中保存完整账号、加密密码和组织归属，使用数据库生成主键；仅管理员可创建账号，新账号为已批准状态。
- 安卓登录页面提示工号，传入 employeeNo 和一致的兼容 username 字段，以精确账号字段查询，不再将邮箱匹配为工号。密码按原始输入发送，保留合法空格。旧版安卓使用 username 字段仍可按工号登录。
- 管理员 Web 登录的页面、用户名/邮箱兼容规则、密码规则、角色限制及会话处理保持原样。只有人员创建和人员资料列将普通账号的业务名称显示为工号。
- 验证创建后工号登录、前导零、全字段落库、必填/无效/重复输入、部门团队联动及后台绕过拦截；回归管理员原登录行为，构建 Web 并检查 Android 资源/源码和 JVM 测试。先审查任务图，不运行 APK 打包或设备测试，不部署服务器。
