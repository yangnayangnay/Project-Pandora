# 每日事项日期选择与个人设置修复

本次由 Codex 直接完成用户明确列出的四项修改，不委派、不部署、不生成或安装 APK。

## 行为

1. 首页每日事项的月份标题、新增和编辑事项中的日期按钮，均复用公司页 `QuickDatePickerDialog`。支持年月日滚轮、直接输入和回到今天；每日事项保持服务端既有的1900—9999年范围，公司页保持原有范围。取消不修改原日期，确认后保留原有日期筛选及事项保存流程。关闭父弹窗或页面时一并关闭日期弹窗。
2. “已完成的任务是否显示”读取和保存现有用户设置接口。公司月、周、日视图、当天任务表及任务明细在加载前读取此值，并传给任务列表接口；客户端同时排除 COMPLETED 和 CONFIRMED，保证完成与确认后的任务口径一致。首页显式选择“已完成任务”的历史看板继续按用户指定的筛选查询，个人每日事项与公司任务保持独立。
3. 设置请求验证业务响应；保存成功后更新本地缓存，失败回退并提示。缓存按服务器和用户隔离，网络读取失败保留该账户最后成功值，无记录默认显示。设置加载/保存时禁用开关，避免旧响应覆盖新选择；程序回显不触发保存，触控与无障碍点击均可保存。
4. 删除设置页“展示前一天日志”的整行布局及请求代码；删除“我的”页“上传数据”整行布局、点击行为、计数查询和相关订阅。既有后台同步、退出时未同步提示与其他设置继续保留。

## 验证

为设置读取、缓存、业务/网络错误、失败回退及任务状态筛选增加 JVM 回归。运行 Java/资源编译、JVM 测试及已有仪器测试源码编译；执行前检查 Gradle 任务图，对比现有 APK 的路径、大小及修改时间，禁止触发打包/安装。源码编译与设备界面验收分别报告。

实际结果：Java/资源、JVM 测试源码及仪器测试源码编译通过；174项 JVM 测试全部通过，其中13项新增回归。130个资源XML及Manifest解析通过，已删除入口在Android源码/资源中无残留引用，`git diff --check`通过。APK路径、大小及修改时间变化数为0；未部署、未打包、未安装，也未运行设备界面验收。验证记录位于 `.build-temp/daily-settings-android-plan.log`、`.build-temp/daily-settings-android.log` 和 `.build-temp/daily-settings-apk-{before,after}.json`。
