# 首页双看板标题与全屏展开

本轮按用户要求统一“事件纪”“任务看板”标题的字号、位置和高度，并增加展开入口。功能实现、集成及最终验证由 Codex 完成；不上传服务器、不生成或安装APK。遵循用户最新要求，后续任务不再委派。

## 设计与交互

- 两侧使用相同的48dp标题行和48dp说明/筛选行。标题均为16sp粗体、垂直居中，展开图标均有48dp触控区与完整无障碍说明，沿用各卡片已有主题颜色。
- 对比只放大原卡片、分别打开两个独立页面、以及共用全屏页：采用共用独立Activity，包含“事件纪／任务看板”两个页签。两张卡片各有展开入口，进入时选中对应页签，任务页签继承首页的未完成/已完成筛选。
- 全屏Activity占据应用内容区，不带首页底部导航，提供工具栏返回和系统返回。没有重新打开MainActivity或清空任务栈的导航操作。
- 事件纪逐条展示完整公司重要事项；任务展示完整名称、正文、状态、人员、时间及已有标签，允许继续打开既有任务详情页。列表支持滚动，不截断长正文。仅使用已有首页聚合接口及其权限范围，不扩展后台可见人员和任务。
- 首次加载、空列表、失败和重试都有明确反馈。页签切换保留各自滚动位置，任务筛选独立于事件纪。

## 返回与生命周期

原首页保留在Activity栈中。首页恢复时使用后台刷新：同一筛选下内容未改变则不重新绘制或显示加载占位，刷新失败保留已有内容；确有更新才重绘并恢复看板滚动位置。每日事项的日期、展开状态和滚动继续使用原控制器状态。

从看板全屏页直接返回且首页View仍存在时，不重新加载不能在该页面编辑的个人事项，避免清空每日清单引起原页面滚动位置变化。若首页View被系统重建，仍执行首次加载，并恢复已保存的日期、展开状态、任务筛选和两侧看板滚动位置。

全屏页保存当前页签、任务筛选及两个列表的滚动状态；关闭时取消请求，避免访问已经销毁的页面。不得为携带列表数据构造可能超过Binder限制的大型Intent或Bundle，展开页按既有接口加载。
