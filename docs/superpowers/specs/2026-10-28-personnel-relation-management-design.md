# 人员关系管理合并设计

日期：2026-10-28

## 目标

将 Web 管理端原“人员关系”和“部门团队”合并为单一的“人员关系管理”模块。该模块同时提供全公司人员安全资料总表、部门团队组织视图、上下级关系视图，以及管理员对职级和组织关系的调整入口。

## 页面结构

复用现有“全员信息与人员关系”页面作为主页面。页面保留人员资料表格、搜索和职级筛选，并增加组织视图区：按部门展示团队和成员。现有关系树、关系列表和关系调整流程并入同一页面。人员详情以弹窗展示所有安全字段；调整表单修改职级、部门、团队和直接上级。

菜单只保留“人员关系管理”入口，原“部门团队”和原“人员关系”路由重定向到合并页面，避免旧链接失效。

## 权限和数据

目录读取允许 ADMIN 和 FOUNDER；ADMIN 可执行职级、部门、团队、直接上级修改以及关系增删，FOUNDER 只读。后端继续使用 `/user/directory`、`/user/directory/options`、`/user/{id}/employment` 和 `/hierarchy/*`，写入接口由后端权限注解保护。

人员总表展示账号、姓名、职级、部门、团队、上下级、邮箱、手机号、身份证号、生日、头像、审批状态、主题设置、显示偏好、创建时间和更新时间。密码哈希、令牌、删除标记和内部审计字段不进入响应。

保存职级或组织关系时，后端在事务中校验职级层级、循环关系、部门团队归属和自我降级限制，并记录既有审计事件。前端保存成功后重新加载目录、组织视图和关系树；移动端继续通过现有接口和同步机制读取变更。

## 验证

验证菜单路由、ADMIN/FOUNDER 权限分支、人员字段渲染、编辑表单提交和组织视图刷新。执行 Web 类型检查/构建、后端测试和关键资源检查。不执行 APK 打包或安装。
