# 首页、公司与每日事项

状态：用户于 2026-11-03 批准方案。本轮由 Codex 直接完成，不委派；禁止打包、复制或安装 APK。

## 用户已明确的需求

1. Android 导图页改名“首页”，视图页改名“公司”，包括底部导航和页面标题。
2. 移除首页的个人十大任务（现有“个人十大重要工作”）和个人日志板块。
3. 左上公司十大重要事项改名“事件纪”；右上公司十大派发任务改名“任务看板”，保持左右位置。
4. 任务执行人能够看到分派给自己的任务。
5. 两个板块下方增加独立于任务的个人每日事项，采用现有月视图的日历样式；上滑收起上方板块，呈现完整日历样式。

## 已批准的细化行为

- 任务看板按当前登录用户作为 assignee 查询全部已生效任务，取消全公司聚合和十条上限。默认未完成，支持切换已完成；本人派给本人的任务也显示。未通过创建审核的申请不作为已生效任务显示。
- 任务看板保留任务名称、状态、派发人及日期，点击进入现有任务详情。完成/确认状态视为已完成，其余原有状态归入未完成。
- 事件纪仅修改首页名称，沿用已有内容、顺序及管理权限。
- 移除首页个人十大和日志的布局、按钮及数据请求；保留日志页、个人十大的其他入口和既有数据。
- 每日事项默认选中今天，可翻月、点击月份选择日期、回到今天。日期上展示事项提示，选日后展示该日个人清单。
- todo 字段为内容、所属日期、完成状态；支持新增、修改内容/日期、勾选完成/恢复、确认删除。内容必填，最长500字；同日可有多条。事项只有一个所属日期，不提供任务派发、审核、标签或任务关联。
- 事项仅当前用户可读写；管理员和创始人均不能通过 ID 或 userId 访问他人事项。服务端根据登录身份确定归属，拒绝客户端传入归属字段。
- 后端持久化事项并按月份读取，重新登录后仍可访问；不与 tasks、任务通知或任务完成率混用。
- 首页初始状态显示上方两个固定高度的独立滚动板块和下方简约月份日历。日历区域上滑时，先收起上方两个板块，再滚动完整月历；展开后日期下展示事项文字，选日清单保留完成操作。
- 日历和事项列表滚回顶部后下拉恢复上方板块；保留可点击的展开/收起入口，日期、月份与清单状态不因切换丢失。
- 完成项弱化显示并附完成文字/勾选状态，避免仅用颜色区分；浅色和深色主题均沿用现有语义资源。

## 实现边界

- 推荐使用原生 AppBarLayout/CoordinatorLayout 与嵌套滚动联动折叠上方两个板块，独立于公司页原有三态月历容器。
- 复用现有 PhoneMonthView 的日期、农历、选日、溢出布局样式；每日事项通过单独适配器提供显示数据，存储模型和接口不使用任务。
- 新增 DailyItemService/Controller、daily_items 表及 Android API/Repository；所有列表及写入查询包含当前用户约束。
- 首页由现有 MindMapFragment 承载，内部类名和导航 ID 无需为文案改名；公司页保留现有任务日历和任务明细功能。
- 首页使用独立首页聚合接口，避免旧版 mindmap 聚合与个人十大/日志的其他消费者受到影响。新接口只返回事件纪和本人任务看板。
- 保留工作区所有现有修改，本轮不部署服务器、不修改实际业务数据库、不扩展 Web 管理端。
